## 3. 먼저 알아 둘 충돌과 위험

답변끼리 서로 부딪히는 부분이에요. 아래 방침으로 풀어 두었고, 바꾸고 싶으면 알려 주세요.

| 충돌 | 왜 문제인가 | 이 계획의 방침 |
|---|---|---|
| 하루 2~3시간 + 오픈 월드 + 10시간 이상 + 다중 엔딩 + 협동 멀티 | 합치면 보통 팀 단위 규모예요. 혼자 하루 2~3시간으로는 완성 전에 지칠 위험이 커요. | 챕터 단위로 쪼개 매 단계가 **플레이 가능한 상태**로 끝나게 해요. 10시간 분량은 최종 목표로 두고 첫 목표는 챕터 1이에요. |
| 서버 저장·로그인 + GitHub Pages + 무료만 | GitHub Pages는 정적 호스팅이라 서버 저장이 안 돼요. 외부 무료 서비스가 필요해요. | 무료 한도가 있는 백엔드 서비스를 쓰는 방향으로 해요. **한도와 약관은 가입 전에 공식 화면에서 확인**해요(미확인). |
| 협동 멀티플레이 + 무료만 + 웹 | 실시간 동기화는 가장 어렵고 서버 비용이 들기 쉬워요. | **마지막 단계**로 미루고, 그 전에 싱글이 완성되게 설계해요. 가능 여부는 무료 한도 확인 후 다시 결정해요. |
| 서버 저장 + 로그인 | 계정·개인정보를 다루게 돼요. | 수집은 최소(이메일 또는 소셜 로그인 중 하나)로 하고, 개인정보 안내 문구를 출시 전에 준비해요. |
| AI 제작 사실을 숨김 + 약관 확인 | 일부 도구는 표기·사용 조건이 있을 수 있어요. | 약관에 따라 크레딧 한 줄 정도는 넣게 될 수 있어요. 6장 체크리스트로 판단해요. |
| 스토리가 깊음 + 적·보스는 최소 | 이야기 분량에 비해 전투 콘텐츠가 부족할 수 있어요. | 챕터 1 안에서 적 3종 + 보스 1로 시작하고 챕터마다 추가해요. |

## 4. 기술 스택 추천

| 영역 | 추천 | 이유 |
|---|---|---|
| 게임 엔진 | **Phaser 3** (웹 2D 프레임워크) | 웹 탑뷰 액션에 널리 쓰이고 AI가 코드를 잘 다뤄요. Godot 웹 내보내기는 아직 확인 못 했어요. |
| 언어 | TypeScript | AI 검토에 유리하고 오류를 일찍 잡아요. 어렵다면 JavaScript로 시작해도 돼요. |
| 빌드 | Vite | 빠르고 GitHub Pages 배포가 쉬워요. |
| 데이터 | JSON 파일 (적·스킬·아이템·대사) | 코드와 분리하면 밸런스 검토와 영어 번역이 쉬워요. |
| 맵 | Tiled 맵 편집기(무료) 또는 코드 생성 | 오픈 월드는 구역을 나눠 불러오는 방식을 써요. |
| 배포 | GitHub Pages + GitHub Actions | 푸시하면 자동 배포돼요. |
| 서버 저장(후순위) | 무료 한도가 있는 백엔드 서비스 | 후보는 가입 전 공식 문서로 비교해요. 지금은 정하지 않아요. |

본 문서의 버전과 서비스 한도는 **구현 시작 전에 공식 문서로 다시 확인**해요.

## 5. 세 AI 역할과 작업 규칙

| 담당 | 역할 | 호출 방법 |
|---|---|---|
| 클로드 코드 (지휘자) | 설계, 핵심 코드, 결과 정리, 최종 판단 | 이 세션 |
| 코덱스 | 코드 검토 (버그·구조·테스트 누락) | `tools\call-codex.ps1 -Model gpt-6-luna` |
| 안티그래비티 | 밸런스·기획 검토 (수치, 난이도, 스토리 흐름) | `tools\call-agy.ps1 -Model gemini-3.8-flash-low` |

규칙
- 직원은 읽기 전용 호출이에요. 직원이 지휘자나 서로를 호출하지 않아요.
- 검토를 맡길 때는 **검토할 파일을 좁은 폴더(예: `review\`)에 복사해서** 그 폴더를 작업 폴더로 지정해요. 이 폴더에 비밀·개인 정보는 두지 않아요.
- 래퍼의 `--sandbox`·plan 모드가 읽기를 완전히 막는지는 입증하지 못했어요. 그래서 키·토큰·계정 정보는 어떤 직원에게도 넘기지 않아요.
- 직원의 지적은 지휘자가 확인하고 반영 여부를 정해요. 직원이 낸 코드를 검증 없이 합치지 않아요.
- 코덱스는 계정에서 `gpt-6-luna`만 확인됐고, 한도·과금은 각 계정 화면에서 확인해요.

## 6. 에셋·저작권 체크리스트

일러스트와 음악은 **수동 단계**예요. 명령줄로 자동 생성하지 않아요.

| 에셋 | 도구 | 사용자가 할 일 | 기록할 것 |
|---|---|---|---|
| 일러스트 | 사용 가능한 챗GPT 이미지 도구 | 제가 쓴 요청문을 붙여 넣어 생성 | 도구 이름, 날짜, 약관의 상업·공개 이용 조건, 표기 의무 |
| 음악·효과음 | AI 음악 생성 도구(무료 플랜) | 도구 선택은 사용자가, 약관은 제가 체크리스트로 정리 | 무료 플랜의 상업 이용 가능 여부, 크레딧 요구 |
| 폰트·기타 | 무료 라이선스 소재 | 출처 링크 보관 | 라이선스 이름 |

- 기록 파일은 `docs\ASSETS.md`에 만들어요(Phase 0).
- 무료 플랜에서 상업 이용이 안 되면 그 에셋은 출시 빌드에서 쓰지 않아요.
- 생성 일관성(같은 캐릭터가 다르게 나오는 문제)을 위해 캐릭터별 기준 설명을 `docs\ART_BIBLE.md`에 적어요.

## 7. 단계별 계획

하루 2~3시간 기준의 **대략적인 규모**예요. 확정 일정이 아니고, 정해진 출시일은 없어요.

### Phase 0. 준비 (1~3일) — [완료 2026-11-22] 배포 주소: https://yeonny3209.github.io/ai-rpg-game/
- 폴더에서 git 초기화, GitHub 저장소 연결 (원격 업로드는 사용자 승인 후)
- Phaser + TypeScript + Vite 프로젝트 만들기, `npm run dev`로 빈 화면 확인
- `docs\ASSETS.md`, `docs\ART_BIBLE.md`, `docs\STORY.md` 뼈대 만들기
- `CLAUDE.md`와 `AGENTS.md`에 이 계획의 규칙 추가
- 완료 기준: 빈 게임 화면이 브라우저에서 뜨고 GitHub Pages에 올라가요.

### Phase 1. 움직이고 싸우기 (약 2~3주) — [구현 완료 2026-11-22 / 사용자 직접 플레이 확인과 안티그래비티 체감 검토 대기]
- WASD 이동, 마우스 조준, 기본 공격, 회피(타이밍 요소)
- 적 1종, 체력·피격·사망
- 임시 도형 그래픽으로 먼저 만들어요(그림은 나중에 교체).
- 완료 기준: 작은 방에서 적과 싸울 수 있어요. 코덱스 코드 검토 1회, 안티그래비티 수치 검토 1회.

### Phase 2. RPG 뼈대 (약 3~4주)
- 직업 2개(전사·마법사), 레벨업, 스킬 3~4개와 간단한 스킬 트리
- 인벤토리, 등급제 장비(무기·방어구·장신구), 드롭
- 적 3종 + 보스 1
- 데이터는 JSON으로 분리해요.
- 완료 기준: 레벨을 올리고 장비를 바꿔 보스를 잡을 수 있어요.

### Phase 3. 챕터 1 (약 4~6주) ← 첫 목표
- 챕터 1 구역 맵(오픈 월드의 첫 구역), 대사·퀘스트 로그, 스토리 컷
- 일러스트·음악 교체, UI(맵·퀘스트 로그·설정)
- 엔딩 분기 구조 확인(챕터 1에서는 분기 표시만, 엔딩은 이후)
- 한국어 텍스트는 문자열 파일로 분리(영어 대비)
- 완료 기준: 처음부터 챕터 1 끝까지 플레이돼요. 친구 2~3명에게 시험 플레이를 받아요.

### Phase 4. 로그인·서버 저장 (약 2~3주)
- 백엔드 서비스 선정(무료 한도·약관 확인 후) → 사용자 가입은 직접
- 로그인, 클라우드 저장·불러오기, 개인정보 안내
- 완료 기준: 다른 브라우저에서 로그인해도 이어서 해요.

### Phase 5. 공개 출시 준비
- 업적·도감, 밸런스 2차 검토, 오류 수정, 약관·크레딧 정리
- 완료 기준: 공개 링크로 안정적으로 플레이돼요.

### Phase 6 이후. 확장
- 챕터 2 이후 콘텐츠, 다중 엔딩 완성, 영어 지원
- **협동 멀티플레이**: 무료 한도 안에서 가능한지 먼저 확인한 뒤 결정해요. 안 되면 비동기 기능(랭킹 등)으로 대체를 제안해요.

## 8. 첫 2주 할 일 (바로 시작용)
